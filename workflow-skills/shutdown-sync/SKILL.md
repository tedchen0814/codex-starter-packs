# 收工同步助手

當使用者說「收工」、「準備換電腦」、「該同步的同步」或明確要求結束工作並同步時使用。一般的「先這樣」「結束了」不算，不確定就先問。

目標是把已完成的實質工作保留在工作筆記與 Git；不把收工解讀為建立 repo、變更可見性或部署網站的授權。

## 執行方式

1. 從目前目錄找出 Git 根目錄，盤點本次對話中完成的工作與 `git status --short` 的變更。若沒有實質變更，說明不需同步並停止。
2. 檢查變更清單。不可加入 `.codex/`、`.claude/`、`.env`、金鑰、credentials 或其他疑似敏感資料；遇到不明的未追蹤檔案或敏感資料時先列出並請使用者決定。
3. 若 repo 根目錄有 `工作筆記.md`，以已驗證的本次工作更新「上次做到哪」、「下一步」與最近更動紀錄；若沒有，回報但不要自建筆記。
4. 只將本次實質變更的明確檔案加入 Git，使用具體的繁體中文 commit 訊息提交。提交前摘要檔案與訊息。
5. 若已有可用 `origin` 與目前分支，推送該 commit。推送失敗時保留本機 commit、回報錯誤與可採取的下一步；不得自行重新登入、建立遠端 repo、改成公開 repo 或部署。
6. 報告工作筆記、Git commit、遠端 push 各自的結果。

## 安全界線

- 「收工」授權同步已確認的當前專案工作，但不授權公開 repo、GitHub Pages、權限變更或其他新的外部服務。
- 不使用 `git add .` 或 `git add -A`；選擇明確檔案。
- 不以自動 hook 執行收工。若使用者要自動化，先說明它會在無人確認時提交或推送，並取得明確同意。
